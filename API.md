# WxBridge HTTP API

Base URL: `http://127.0.0.1:8787`. All endpoints, including health checks and
file downloads, require a bearer token. The examples use the private token
file generated by the server:

```sh
WXBRIDGE_TOKEN=$(cat state/api-token)
curl -H "Authorization: Bearer $WXBRIDGE_TOKEN" http://127.0.0.1:8787/v1/status
```

## Login

```sh
curl -X POST -H "Authorization: Bearer $WXBRIDGE_TOKEN" http://127.0.0.1:8787/v1/login/qr
curl -H "Authorization: Bearer $WXBRIDGE_TOKEN" http://127.0.0.1:8787/v1/login/qr/image -o qrcode.png
curl -X POST -H "Authorization: Bearer $WXBRIDGE_TOKEN" http://127.0.0.1:8787/v1/login/check
```

Scan and confirm in WeChat, then call `login/check` again. When QR state is 2,
the endpoint performs formal authentication. Generating another QR while an
authenticated session exists is rejected. QR polling is explicit; background
message synchronization starts after authentication.

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/healthz` | Process health |
| GET | `/v1/status` | Saved login state, last sync/heartbeat and background error |
| GET | `/v1/capabilities` | Tested and unverified capability groups |
| POST | `/v1/login/qr` | Generate a QR for a new session |
| GET | `/v1/login/qr/image` | Download the QR image |
| POST | `/v1/login/check` | Check scan status and authenticate after confirmation |
| POST | `/v1/heartbeat` | Verify the live session |
| POST | `/v1/contacts/lookup` | Look up one exact username |
| POST | `/v1/uploads` | Upload raw file bytes, maximum 32 MiB |
| POST | `/v1/messages/text` | Send text |
| POST | `/v1/messages/image` | Send PNG/JPEG |
| POST | `/v1/messages/emoji` | Send an existing sticker by MD5 and byte size |
| POST | `/v1/messages/gif` | Upload/send custom GIF bytes |
| POST | `/v1/messages/voice` | Send encoded AMR-NB/SILK audio |
| POST | `/v1/messages/video` | Upload/send MP4 and JPEG thumbnail |
| GET | `/v1/messages?cursor=0&limit=100` | Non-destructive message polling |
| POST | `/v1/sync` | Perform one additional synchronization request |
| POST | `/v1/media/{message_id}/download` | Download a saved media message |
| GET | `/v1/media/{message_id}` | Read a completed downloaded file |

## Send Text

```sh
curl -X POST http://127.0.0.1:8787/v1/messages/text \
  -H "Authorization: Bearer $WXBRIDGE_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: my-project-message-0001' \
  -d '{"to":"filehelper","text":"Hello from WxBridge"}'
```

`to` must be an exact WeChat username, not a nickname. A successful send returns:

```json
{"ok":true,"result":{"kind":"text","recipient":"filehelper","message_id":"1234567890123456789","server_accepted":true}}
```

The message ID above is illustrative. Server acceptance does not prove the
recipient displayed or played the message.

## Send Media

First upload a file as the raw request body, not multipart form data:

```sh
curl -X POST http://127.0.0.1:8787/v1/uploads \
  -H "Authorization: Bearer $WXBRIDGE_TOKEN" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @image.png
```

Use the returned `upload_id` in a message request. All message endpoints need
`Content-Type: application/json` and `Idempotency-Key` headers.

| Endpoint suffix | JSON fields |
| --- | --- |
| `image` | `to`, `upload_id` |
| `gif` | `to`, `upload_id` |
| `emoji` | `to`, `md5`, `size` |
| `voice` | `to`, `upload_id`, `duration_ms` |
| `video` | `to`, `upload_id`, `thumbnail_id`, `seconds` |

Image limit: 20 MiB and 20 million pixels. GIF limit: 5 MiB, 200 frames and
bounded decoded pixels. Voice limit: 1 MiB and 60 seconds; audio must already
be encoded as AMR-NB or SILK V3. Video limit: 20 MiB MP4, 1 MiB JPEG thumbnail,
and 1 to 600 seconds. Upload the thumbnail separately to obtain `thumbnail_id`.
The service does not run FFmpeg or infer audio/video duration.

## Receive and Download

Poll `/v1/messages` using the returned `next_cursor`; optional `peer=USERNAME`
filters a conversation. The cursor belongs to this state directory. Responses
contain string message IDs, sender, recipient, numeric type and creation time.
Text is included for text messages. Media messages expose `media_kind` and,
once processed, a `media` record and authenticated `download_url`.

```sh
curl -H "Authorization: Bearer $WXBRIDGE_TOKEN" \
  'http://127.0.0.1:8787/v1/messages?cursor=0&limit=100'
curl -X POST -H "Authorization: Bearer $WXBRIDGE_TOKEN" \
  http://127.0.0.1:8787/v1/media/MESSAGE_ID/download
curl -H "Authorization: Bearer $WXBRIDGE_TOKEN" \
  http://127.0.0.1:8787/v1/media/MESSAGE_ID -o received-media
```

Automatic downloading handles new incoming image, sticker, voice and video
messages. This receiving path has offline coverage but has not been verified
against real incoming media. Failures are explicit; a partial download is
never served as a completed file. CDN credentials are kept out of the message
projection returned by the API.

## Retry Rules

Use one `Idempotency-Key` per intended message. Same key and same payload:
the saved response is replayed with `Idempotency-Replayed: true`. Same key and
different payload: HTTP 409. Interrupted submission after restart: HTTP 409
with `delivery_unknown: true`; inspect the conversation before using a new key.

Validation errors use HTTP 400; missing/incorrect token uses 401. Upload size
violations use 413; unavailable media uses 404. Upstream failures generally
use 502 and may include a partial receipt. An HTTP error is not permission to
send the message again: check `server_accepted` and delivery first.
